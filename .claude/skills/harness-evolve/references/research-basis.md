# Research basis

What this skill takes from each source, and what it deliberately does not. Read 2026-10-05 (papers via arXiv abs/html, code via cloned repos).

| Source | Taken | Left behind |
|---|---|---|
| **Self-Harness** (arXiv 2606.09498) | The acceptance rule: Δ_in ≥ 0 AND Δ_holdout ≥ 0 AND max > 0, decided by re-running tasks, never by the proposer's rationale. Failure signature as (cause, behaviour, mechanism), exact-signature clustering. Per-edit audit record {target_pattern, surface, expected_effect, regression_risk}. Minimal single-pattern edits. | No retry baseline reported; the paper's gains (+7% to +132%) are initial-vs-final only. |
| **HarnessEvolve** (arXiv 2609.00829) | Cheap quality gate before expensive re-execution: leakage check (no eval inputs copied into the harness), bloat cap. Cluster by cause not severity. Replay buffer idea → our regression suites. Ablation: removing the quality gate cost 6.8 pts, removing clustering 18 pts. | Reference-trajectory generation (answer-in-hand reruns) needs ground-truth answers per task; most agent-harness tasks have none. Left as a future `run` task pattern. |
| **ACE** (ICLR 2026, arXiv 2510.04618, github.com/ace-agent/ace) | The playbook: append-only bullets `[slug-NNNNN] helpful=N harmful=N :: text`, generator declares which bullets it used, reflector tags helpful/harmful. Context collapse evidence: one full rewrite 18,282 → 122 tokens, accuracy below baseline. Stats heuristics (high-performing helpful>5 & harmful<2; problematic harmful ≥ helpful > 0). | ACE's shipped code never prunes and has no per-edit gate; this skill adds `playbook prune` and gates everything above tier 0. |
| **Continual Harness** (arXiv 2605.09998, github.com/sethkarten/continual-harness) | Deterministic pre-LLM failure extraction (tool `is_error`, loop detection, antipattern counters) → our `collect`. Adaptive cadence (dense early, back off). Per-store JSON CRUD with `source=evolved` provenance. | It has no gate at all; its own Red run regressed below the minimal harness and Flash-Lite got worse under every variant. |
| **Prime Agent** (arXiv 2608.23552, §2.5 + `/refine`) | Edits as versioned overlay entries carrying {trigger, intended_effect, version}; never rewrite the base prompt; apply at a turn boundary; rollback by version. | No gate. Its Factorio run persisted an RCON reward-hack as a reusable skill: the reason tier 3 exists and the loop can't edit its judge. |
| **Hermes self-evolution** (github.com/NousResearch/hermes-agent-self-evolution @0a929e3) | Hard constraints as the first gate: max size, ≤20% growth, frontmatter identity frozen. 50/25/25 split with a holdout. Never write to the live tree (output dir / branch). Session mining with a secret regex. "Benchmarks are GATES, not fitness functions." Commit template `evolve: <target> — ...`. | Phase 1 only; holdout comparison is advisory there. Here it blocks. |
| **Rethinking the Evaluation of Harness Evolution** (arXiv 2607.12227) | The protocol: disjoint train/val/holdout; matched budget; evolved harness must beat **best-of-K with the same verifier**; pass@1 primary; overfit meter = train gain − holdout gain; prefer tests over self-judgment. Their numbers: harness evolution 67.4 vs direct sampling 68.2 vs best-of-5 72.3 (no tests); on a disjoint split the evolved harness gained **+0.0**. Wins came only where the artifacts were executable tools, not prose. | Nothing. This paper is the reason the gate is strict. |
| **Agentic Harness Engineering** (arXiv 2604.25850) | Change manifest with predicted_fixes / predicted_regressions, verified next cycle, revert at file granularity. Their fix-prediction precision 33.7%, regression prediction 11.8% (≈ random) → predictions are logged, never trusted; the holdout and suites do the real work. | Evaluated on the tasks it optimised. |
| **SkillRevise** (arXiv 2606.01139) | Diagnose before edit; `harness_at_fault` verdict; preservation ledger (`preserve[]`); keep S0 in the candidate set; unstructured repeated revision scored **worse than no skill** (33/86 vs 31/86). | Principle memory retrieval (BM25+dense) — overkill for a repo skill. |
| **QM** (github.com/yc-software/qm) | "Never self-review in the authoring context" → producer/judge separation. Skill packs enter via pinned ref + review + trust tier → our tiers and `--human-approved`. | It is a runtime, not an evolution loop. |
| **OpenJarvis** spec-search (arXiv 2605.17172 §3.3) | Per-cluster gate: must improve the target cluster, no other cluster drops > ε = 1%; stop after 5 stagnant rounds. | TOML spec search over model/engine primitives. |
| **Self-grading inflates** (arXiv 2511.23092) | Inflation 0.92 on summarisation, 0.20 sentiment, ~0 arithmetic → the producer never grades; prefer deterministic `check` over `judge`; the loop cannot write to the eval set or judge prompt. | |
| **Position bias** (arXiv 2406.07791) | ~1 in 4 pairwise verdicts flip when A/B are swapped (PC ≈ 0.73; best judges 0.82–0.89). Both orders must agree, else tie. Near-equal candidates are the danger zone, which is exactly what a harness gate compares. | Multi-judge majority (add if a single judge's consistency on calibration pairs is < 0.8). |

## What the evidence implies for a drop-in skill

1. Build the eval before the loop. Without a holdout and a best-of-K baseline there is no way to tell evolution from retries, and the one rigorous study found +0.0.
2. Deterministic checks carry most of the value and cost nothing: retired references, dead paths, unrouted skills. That is where this repo's real drift was (80 live references to a project retired a month earlier; the most-used skill absent from CLAUDE.md).
3. Prose rules are the weakest artifact to evolve. Where a lesson can be a check, a hook, or a script, prefer that (the Rethinking paper's wins were executable tools; the `reflect` skill's "structural enforcement" rule says the same).
4. Only the playbook auto-lands, because it is append-only, per-bullet attributable, and cheap to prune.
